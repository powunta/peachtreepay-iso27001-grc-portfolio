# How to explain this project in a GRC interview
## 30-second description
“I created a fictional outpatient clinic to practice healthcare security governance. I defined ePHI data flows, scored 12 risks, mapped ten sampled control areas to HIPAA Security Rule safeguards, tested synthetic termination access records and recommended a 90-day remediation roadmap. The main finding was inconsistent offboarding against a simulated clinic policy, so I proposed automation, independent verification and retesting.”

## Common questions
**Why HIPAA?** Healthcare security involves confidentiality, integrity and availability with direct patient-care implications; I wanted to apply general ISO/NIST concepts in a different regulatory context.

**How did you score risk?** A transparent 5×5 inherent likelihood-impact matrix, with Critical 20–25, High 12–19, Moderate 8–11 and Low 1–7. Residual risk targets are planning estimates, not independently measured outcomes.

**What did the access test prove?** In a synthetic 24-account sample, four cases exceeded a fictional 24-hour policy. That supports a simulated control-effectiveness finding, **not a claim of an actual data breach**.

**What does addressable mean?** It does not mean a HIPAA safeguard can be ignored. A regulated entity must evaluate implementation and documented alternatives against the applicable rule.

**How would you handle uncertainty?** Seek source evidence, distinguish missing proof from confirmed failure, and consult the privacy officer/legal specialists for regulatory determinations.

**What would you improve next?** Obtain realistic audit artifacts, document retest procedures and expand the asset inventory without collecting real ePHI.

**Professional integrity:** Always say *simulated portfolio project*, not *client audit*, *employment experience*, or *certified HIPAA assessment*.
